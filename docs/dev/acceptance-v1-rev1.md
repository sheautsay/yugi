## 2. 判定細則

### G13
1. `docs/deck-code-feasibility.md` 存在，含來源、範例、測試、失敗案例、限制、結論（GO／NO-GO／BLOCKED）；沒有使用者提供的實際代碼範例時，結論必須是 BLOCKED。
2. 未取得 GO 前，任何畫面不得宣稱支援遊戲內代碼；輸入無法判別的格式時，不產生、不修改任何牌組，並提示「遊戲內代碼仍在研究中，請改用 ydke:// 或 YDK」。
3. 統一匯入框能自動判別 `ydke://`（含前後空白、換行）與 YDK 原文，並分別通過與 G1、G2 相同的檢核；判別結果與直接使用對應 parser 一致。
4. 自動判別不得讓任何 G1／G2 負向案例變成成功。

### G14
1. 選擇檔案、拖放、剪貼簿貼上三種入口都能載入圖片並顯示。
2. 拒絕：非圖片類型、超過 20 MB、寬或高超過 8192 px、解碼失敗、剪貼簿沒有圖片；每種都顯示原因與下一步，且不改動目前手牌。
3. 截圖不寫入 IndexedDB、不出現在任何網路請求中；離開頁面或確認後釋放（object URL revoke）。
4. 程式碼不使用 `getDisplayMedia` 或其他螢幕擷取 API。

### G15a
1. 辨識輸出的卡片 ID 只可能來自目前牌組主牌。
2. 指派結果每個 ID 的張數 ≤ 主牌張數；超出時分數較低的格必須為 `uncertain`，不得默默改成其他卡。
3. 無參考圖 → `unrecognized`；分數或差距未達門檻 → `uncertain`；狀態以文字顯示。
4. 存在 `uncertain`／`unrecognized` 或框數 ≠ 手牌張數時，「確認手牌並查詢」不可用；使用者確認後，手牌狀態與手動選牌完全等價，並經同一比對器查詢。
5. 合成測試（以卡圖合成之縮放、壓縮、亮度變化影像）可驗證流程與演算法基線；**合成結果不得作為 G15b 證據**。

### G15b
1. 實際 Master Duel 截圖測試集的張數、正確率、「高信心但辨識錯誤」上限，於 PoC 後以 CR 鎖定，鎖定前狀態為 BLOCKED。
2. 未鎖定、未執行時，不得宣稱辨識準確率達標。

### G16
1. 先攻手牌 5 張、後攻手牌 6 張；任何輸入方式下同一 ID 選取數 ≤ 主牌張數。
2. 後攻隨機抽 6 張為不放回抽樣，相同 seed 結果相同。
3. 先後攻切換時，手牌多於新張數不自動刪除且不能查詢；少於新張數視為未選滿、不能查詢。
4. `unallocatedHandMin` 以實際手牌張數計算（例：A×1、剩 5 張代價 — 6 張手牌含 A 為符合；5 張手牌仍依 `acceptance-v1.md` M6 為不符合）。
5. `turnOrder: 'first'` 路線在後攻情境、`'second'` 路線在先攻情境皆為 `CONTEXT_MISMATCH`，不得為 `available`；`'either'` 兩者皆可。
6. `acceptance-v1.md` 的 G4、G5 原有 5 張案例全部維持通過。
