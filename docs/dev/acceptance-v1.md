## 1. 結果狀態定義

| 狀態 | 意義 |
|---|---|
| PASS | 已實際執行，所有判定條件成立，有命令／退出碼／輸出證據 |
| FAIL | 已實際執行，至少一項判定條件不成立 |
| NOT_RUN | 尚未執行（含時間、順序因素） |
| BLOCKED | 缺少必要條件而無法執行（需寫明缺少什麼、下一次所需條件） |

- skipped、mock、NOT_RUN **不得**寫成 PASS。
- 以 mock 取代外部服務（例如卡片 API）的測試，只能證明「本程式在該假設回應下的行為」，紀錄中必須標示為 mock；真實外部服務的行為另列項目。

## 2. 不可變更的驗收原則（規格 §7.1 原文）

- 實作前在 `docs/acceptance-v1.md` 固定以下 Gate；之後不能透過刪測試、降低目標、改預期值來讓失敗變 PASS。
- 如果原規格本身確有錯誤，只能另開**顯式變更記錄**、記下原因／影響／核准者，不得暗改舊驗收證據。
- 測試失敗：分析根因 → 修正實作 → 重跑失敗測試 → 跑相關回歸 → 跑整體 Gate。
- 測試結果分 `PASS / FAIL / NOT_RUN / BLOCKED`，**不把 skipped、mock 或 NOT_RUN 寫成 PASS**。
- 不為反覆測試建立新分支；本機開發完成，Gate PASS 後才合併本機 `main`。

## 3. Gate 清單（規格 §7.2 原文）

| Gate | 固定驗收目標 | 建議驗證方法 |
|---|---|---|
| G0 | 專案可啟動、strict 編譯、測試及 production build 成功 | CLI logs、版本清單 |
| G1 | YDK 三區與張數正確；處理重複 ID、BOM、CRLF、錯誤行與空行 | parser unit tests |
| G2 | YDKE little-endian uint32、三區與空區正確；不合法 base64／長度拒絕 | specification vectors + tests |
| G3 | 牌表 ID／張數／區域不混淆；輸入無效時不得假成功 | unit + UI tests |
| G4 | 五張選牌不超配；不放回抽牌；隨機測試可重現 seed | unit + UI tests |
| G5 | AND/OR 數量不可重複消費；含代價／剩餘主牌／額外要求 | matcher unit tests |
| G6 | 沒有收錄路線時不斷言「不能展開」；未驗證不得冒充 PASS | UI tests |
| G7 | A/B 共用 currentStep，來回切換、超界／空路線行為正確 | component/E2E |
| G8 | Combo 編輯、保存、匯入／匯出、版本／驗證狀態與錯誤資料防護 | unit + E2E |
| G9 | IndexedDB 關閉重啟資料保持；備份後重建可還原 | integration/E2E |
| G10 | 狹窄視窗可正常觀看文字與流程，繁體中文不缺字／無主要控制被遮住 | screenshot + 手動紀錄 |
| G11 | 無 GitHub 遠端／push，不讀遊戲內存，不新增未批准網路服務 | `git remote -v` + code audit |
| G12 | 至少 **1 條碼莉絲固定 Combo 經人工按原路線實測、留有 evidence**；沒有實測就不能顯示 verified | 實測檢核單／影像或文字證據 |

**G12 說明（原文）**：第一條已驗證路線是 V1 最小交付門檻；後續擴充 5–10 條常用路線屬內容建設，不得以模型虛構路線代替。若缺少可實測的卡片環境或牌表，必須如實回報 `BLOCKED`，其餘功能仍可分項驗收，不可謊稱整體 PASS。

## 4. Gate 判定細則（由規格條文展開，只可更嚴格、不可放寬）

每一條都要有對應的自動化測試或明確的手動證據；任何一條不成立，該 Gate 即 FAIL。

### G0（規格 §2、§8 V0）
1. TypeScript `strict: true` 與 Angular strict templates 開啟，`ng build`（production）退出碼 0。
2. 單元測試命令退出碼 0，且測試數 > 0、無 skipped 被計為通過。
3. 開發伺服器可啟動並回應首頁（HTTP 200），首頁為繁體中文殼與路由（§6.1 五個路徑皆可導航）。
4. 記錄 Node／npm／Angular CLI／主要套件實際版本；`package-lock.json` 存在。

### G1（規格 F02）
1. `#main`、`#extra`、`!side` 三區分開；每一數字行代表一張卡；重複行累加張數；同區同 ID 只有一列。
2. 處理 UTF-8 BOM、LF／CRLF、前後空白、空行；忽略其他標頭註解，註解不可被辨識為卡片。
3. 非整數、負數、超界、無法解析的行：逐行（含行號）列出錯誤，且整體不回傳成功。
4. 未出現在任何區段之前的數字行不可默默歸入某區。
5. UI：解析成功後顯示三區張數與預覽，使用者按「確認」才寫入；取消不改動既有牌組。

### G2（規格 F03）
1. 格式 `ydke://<main>!<extra>!<side>!`，三段各自 base64；尾端 `!` 為格式一部分。
2. 每張卡 uint32 little-endian；解碼長度非 4 的倍數即拒絕。
3. 空的額外／備牌允許；重複 ID 累加張數。
4. 空字串、缺分隔符、非法 base64、長度錯誤 → 拒絕並列出清楚原因；未識別卡片 → 不得為「完整成功」。
5. 必須通過 §6.2 的規格書已知向量，並有「匯入後張數比對」測試。

### G3（規格 F01、§4.2）
1. 牌組以 `cardId + count` 儲存，三區不混淆；`isExtraDeckType` 不得改寫原始匯入區域。
2. 主牌 40–60、額外 0–15、單卡 ≤3 的檢核；不合格者只能是草稿，不能進入五張抽牌的正常模式。
3. 有無法辨識的卡片 ID：顯示失敗明細、不默默略過；可存草稿但不得標示可供正式查詢。
4. 匯入失敗或取消不得污染既有資料；顯示主牌／額外／備牌總張數。
5. 明示尚未進行當期禁限核對（禁限不作硬阻擋）。

### G4（規格 F05）
1. 只能從目前有效牌組的**主牌組**選；手牌固定 5 張；同 ID 選取數 ≤ 主牌中的張數；複數張以數量徽標顯示。
2. 隨機抽五張為依主牌實際張數的不放回抽樣；給定相同 seed 結果相同（可重現）。
3. 未選滿 5 張不能進入正式查詢；清除、刪除一張、重新抽牌、恢復前一個有效手牌皆不改動牌表。
4. 牌組內容被修改後，舊手牌若不再有效必須被偵測，不得沿用。

### G5（規格 F06、§4.3、§5）
1. 起手要求為多重集合；AND/OR 共享數量分配，同一張卡不得被分配兩次（回溯或等價正確演算法）。
2. `unallocatedHandMin` 扣除已分配卡片後計算，不重複計為代價。
3. `mustRemainInMain` = `deck.main[cardId] - openingHand[cardId]`；額外需求只比對 `extra`。
4. `forbiddenInHand`、前置情境（先後攻、空場、通常召喚、無干擾）有對應判定與原因碼。
5. 比對為純函式：不修改 `DeckRecord`／`ComboRoute`，相同輸入相同輸出。
6. 必須通過 §6.1 全部示例判斷案例。

### G6（規格 F06、§4.5、§5）
1. 無符合路線時顯示「沒有收錄符合目前起手的固定展開」，**不得**出現「無法展開」等斷言。
2. `available` 只用於驗證狀態允許且所有條件均滿足的路線；`draft`／`unverified`／`invalidated`、牌表版本（指紋）不一致、缺少必要狀態資料者不得標為可用。
3. 顯示「可用」「不符合（含原因）」「未驗證」「無收錄路線」等明確狀態；不顯示勝率百分比。
4. 預設排序：已驗證且符合 → 固定排序權重 → 起手需求較少 → 名稱。

### G7（規格 F07、F08、§6.2）
1. A／B 兩模式共用單一 `currentStep`；A 點第 k 步 → 切 B 仍為第 k 步，反之亦然。
2. 上一步／下一步／指定步驟不得超出 1..N；最後一步按下一步不超界。
3. 鍵盤方向鍵可切換步驟，但焦點在文字輸入框時不攔截；有鍵盤可用的按鈕。
4. 切換路線時重置至第 1 步；空步驟路線顯示待補內容且不能為 `verified`。
5. A 模式每節點有序號、卡圖（或 fallback）、操作摘要、可展開說明；未提供欄位明確標「未填」；顯示終場。
6. B 模式顯示「第 k / N 步」、動作、位置、目標、素材、結果、原因、注意事項；精簡模式不得隱藏注意事項。

### G8（規格 F09、§4.4 安全界線）
1. UI 可新增、複製、編輯、刪除（二次確認）Combo；步驟可新增、刪除、上移、下移、指向卡片 ID。
2. `verified` 只有在具備驗證證據、實測日期、牌表前提（指紋）、驗證者、且步驟非空時才可設定。
3. 草稿可存但不得顯示為已驗證可用；`schemaVersion` 受控，未知版本拒絕。
4. JSON 匯入：先檢核 schema、卡片 ID、引用完整性，再預覽、確認後才寫入；拒絕 script／任意 HTML／未知可執行指令；步驟為空、重複 step ID、缺必填、未知卡、惡意 URL scheme 皆拒絕。
5. 來源網址只允許白名單 `https://` 來源、開新分頁；所有文字以純文字渲染，不使用 `eval`／`innerHTML` 插入資料。
6. 匯入錯誤或存檔中途失敗不得污染原有資料、不留半成品。

### G9（規格 F11）
1. 資料存於 IndexedDB；瀏覽器關閉重啟（同一設定檔）後牌組與 Combo 仍存在。
2. 匯出完整使用者資料 JSON（不含卡片圖片）；於空資料環境預覽後還原，內容一致；處理重名與 ID 衝突。
3. 設定畫面提示 IndexedDB 可能被清除、需定期備份。
4. 無網路／API 失敗時，已存的牌組與路線仍可開啟，缺資料明確標示。

### G10（規格 F07、§6.2）
1. 視窗寬 360、390、420 CSS px 下，主要頁面無水平捲動造成的文字裁切，主要操作按鈕可到達。
2. 步驟文字（B 模式）與流程（A 模式，可捲動）可閱讀；繁體中文字元正常顯示。
3. 證據：各寬度截圖＋檢查紀錄（記錄檢查者）。

### G11（規格 §1.2、§9）
1. `git remote -v` 輸出為空；未執行 `git push`／`gh repo create`。
2. 程式碼稽核：無讀取遊戲記憶體、封包、私有 API；無自動操作；外部網路請求僅限 YGOPRODeck 公開卡片資料（API 與圖片），並經統一 adapter、節流、重試／退避。
3. 無 API 金鑰／密碼／Cookie／Token 存於程式或版控；不要求使用者提供 Steam 帳號等資料。

### G12（規格 §7.2 G12 說明）
1. 至少 1 條碼莉絲固定 Combo 有人工依原路線實測的 evidence（日期、牌表指紋、驗證者、證據說明）。
2. 無實測證據時，該路線不得顯示 `verified`，G12 必須回報 `BLOCKED`。

### 6.1 比對示例（規格 §5 原文；A/B/C 為測試用抽象 cardId）

| # | 起手要求 | 手牌 | 預期 |
|---|---|---|---|
| M1 | A ×1 | A+B+C+D+E | 起手條件符合 |
| M2 | A ×2 | A+B+C+D+E | 不符合：缺少一張 A |
| M3 | A 或 B ×1 ＋ A ×1 | A+B+C+D+E | 符合：一張 A、一張 B |
| M4 | A 或 B ×1 ＋ A ×1 | A+C+D+E+F | 不符合：不能把一張 A 分配兩次 |
| M5 | A ×1，額外剩 1 張代價 | A+B+C+D+E | 符合 |
| M6 | A ×1，額外剩 5 張代價 | A+B+C+D+E | 不符合 |
| M7 | 牌組內須仍有 B ×1 | 起手拿走最後一張 B | 不符合 |
| M8 | 額外需要 C ×1 | 額外沒有 C | 不符合 |

## 7. 階段與 Gate 對應（規格 §8）

| 階段 | 工作 | Gate |

## 8. 驗收證據格式（規格 §7.4）

每階段產出 `docs/validation/<gate-id>-<date>.md`，需包含：分支與 commit、環境版本、執行命令、退出碼、實測結果、差異、修正、回歸、限制。無法執行時明確列出原因與下一次所需條件。

## 9. V1 最終成功定義（規格原文）

本機可啟動的 Angular 工具，能匯入真實牌表、選五張起手、找出符合完整條件的**已驗證固定路線**，用 A/B 兩種模式檢視同一份步驟，完整保存與備份個人資料，並具備可追溯的自動化測試與至少一條人工驗證的碼莉絲 Combo。**不把 PoC、未驗證路線或假資料當成正式成功。**
