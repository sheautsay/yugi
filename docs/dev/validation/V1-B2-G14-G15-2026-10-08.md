## 判定細則對照

### G14（acceptance-v1-rev1 §2）
| # | 證據 |
|---|---|
| 1 選檔／拖放／貼上 | E2E：`setInputFiles` 上傳、`drop` 事件、`ClipboardEvent('paste')` 三種入口皆顯示「已載入截圖（寬×高）」 |
| 2 拒絕非圖片、>20 MB、>8192 px、損毀、剪貼簿無圖；不改手牌 | unit `screenshotFileError`／`screenshotSizeError`；E2E N9：txt、損毀 PNG、8200×10 PNG、空剪貼簿各顯示原因與下一步，手牌維持 1 / 5 |
| 3 不存 IndexedDB、不上傳、確認後釋放 | E2E：整段流程所有請求皆為無 body 的 GET，外部請求只到卡片來源；IndexedDB 除 `images`（鍵為 `small:ID`／`cropped:ID`）外無任何 Blob；確認後預覽區消失（object URL 已 revoke、bitmap 已 close） |
| 4 不使用螢幕擷取 API | `npm run audit:g11` 掃描無 `getDisplayMedia`／`getUserMedia`／`captureStream` |

### G15a
| # | 證據 |
|---|---|
| 1 候選只來自主牌 | unit：參考圖中加入非主牌卡，候選永不出現該卡 |
| 2 不超配、超出改 uncertain 不換卡 | unit N10：牌組只有 1 張但兩格最佳都是該卡 → 分數高者保留，另一格 `uncertain` 且未自動改卡（原卡仍列為候選建議） |
| 3 無參考圖 → unrecognized；缺部分參考圖 → 不可 confident；狀態文字顯示 | unit N10 兩案例；畫面徽章文字「辨識信心高／不確定，請選擇正確的卡／無法辨識，請選擇正確的卡／已手動選擇」 |
| 4 未解決或框數 ≠ 張數不可查詢；確認後與手動選牌等價 | E2E：0／1 框時「開始辨識」停用；不在牌組的卡那一格非 confident，「確認手牌並查詢」停用；選擇後才可確認，結果寫入同一手牌狀態並經同一比對器查詢 |
| 5 合成測試只作演算法基線 | unit 合成資料（20 張、3 種亮度 × 3 種框偏移 × 雜訊，共 180 例）：**高信心錯誤 0**、top-1 ≥ 95%、confident ≥ 80%；牌組外的 40 張卡均未被判為 confident。此結果**不作為 G15b 證據** |

### G15b
- 狀態 **BLOCKED**：需要使用者提供實際 Master Duel 起手截圖（建議 ≥ 20 張，含先攻 5 張與後攻 6 張）及每張正確手牌，PoC 後以 CR-002 鎖定張數、正確率、高信心錯誤上限。
- 目前畫面標示「截圖辨識（實驗性）」並說明「辨識準確率尚未以實際截圖驗證，結果一律需由你確認」。

## 實作過程中的失敗與修正

| 失敗 | 根因 | 修正 |
|---|---|---|
| 合成測試 confident 比例 62%（目標 80%） | 使用者框線有 ±3% 偏移時相似度下降 | **程式修正**：每格以 9 個微小位移的插畫窗口比對、取最佳分數；**門檻未調低**。重跑：高信心錯誤 0、top-1 ≥ 95%、confident ≥ 80% |
| 合成測試逾時（5 秒） | 測試輔助用純 JS 重取樣，計算量為 9 倍 | 該測試逾時設為 60 秒；斷言未改 |

## 限制

- 卡圖插畫區位置使用標準（非靈擺）卡框比例；靈擺卡插畫區不同，可能較常判為不確定（需實際截圖驗證）。
- 預設框位（畫面下方中央）只是起點；Master Duel 實際手牌位置、重疊、異圖與卡面特效對準確率的影響尚未驗證（G15b）。
