# 實戰模式（Battle Mode）規格

> 建立日期：2026-10-18｜狀態：設計定稿，**待 `docs/optimization-plan.md` 的 P1～P5 合併進 main 後再開始實作**（兩者會修改同一批頁面）。

## 目標

玩 Master Duel 時，在幾秒內知道「這手牌能做什麼、哪個終場最強、下一步怎麼走」。

AI 分析太慢，無法在對局中即時進行，所以分成兩段：

1. **賽前（不趕時間）**：匯入牌組 → AI 分階段分析 1～3 張起手的展開 → 一次把所有可用路線存成 Combo。
2. **實戰（越快越好）**：辨識目前手牌 → 從已存的路線中找出符合的 → 依終場強度列出前 3～5 名 → 選一條後顯示精簡步驟與最終終場。

## 已確認的決定

| 項目 | 決定 |
|---|---|
| 遊戲環境 | Master Duel Steam 版，**視窗模式**，與本程式在同一台電腦 |
| 「最大終場」定義 | 沿用 AI 分析頁既有的目標 A～E（`src/app/core/ai/analysis-goal.ts`），實戰預設 A「最大化終場有效干擾」，可臨時切換；之後不夠用再調整 |
| 已實測 / 未實測路線 | **混在一起排序**，只看終場分數；已實測的加「已實測」標記，僅在分數完全相同時優先 |
| 手牌辨識準確度 | 尚未驗證，**先不處理**；若實作後準確度不足，再用實際截圖評估並改進辨識（見「風險」） |

## 必須遵守的原則

- **不讀遊戲記憶體、不注入、不自動操作**。只在使用者按下快捷鍵時截取一次 Master Duel 視窗畫面，截圖只在記憶體中處理，不存檔。
- 延續既有原則：資料只存在本機；「已驗證」只能由使用者實測後設定；AI 路線永遠標示為候選。
- KONAMI 使用條款對第三方輔助工具沒有明確界線；被動截圖風險較低，但無法保證。設定中要有說明，且整個實戰模式預設為關閉、由使用者自行啟用。

## 開發階段

每個階段各自一個分支與 PR，都必須通過 `npm run build`、`npm run test:ci`、`npm run test:bridge`，並為新邏輯補單元測試。

### B1｜依終場強度排序

- 新增一個「實戰排序」函式（建議放 `src/app/core/battle-rank.ts`）：輸入 `matchRoutes()` 中 `kind` 為 `available` 或 `unverified` 的結果，對每條路線呼叫 `evaluateRoute()`，再依所選目標排序。排序邏輯重用 `evaluate.ts` 的 `score()`（必要時將其 export，或抽成共用函式），不要複製一份。
- 排序規則：終場分數 → 已實測優先（僅同分時）→ 需要的手牌張數少者優先 → 名稱。
- 終場完全相同的路線（`signature` 相同）合併顯示，只保留排名最高的一條，其餘標示「另有 N 條相同終場」。
- 既有起手查詢頁（`hand-page`）的排序**不變**；實戰排序只用在新的實戰模式。
- **驗收**：單元測試涵蓋 A～E 五種目標的排序、同分時的實測優先、相同終場合併。

### B2｜AI 路線批次存檔

- AI 分析結果頁加「全部存成 Combo」：一次儲存所有通過本機檢查（`valid`）且尚未存過的候選路線，使用既有的 `saveCandidate` 流程與單一 IndexedDB transaction（參考 `combo-repository.ts` 的批次寫入）。
- 儲存前顯示數量確認；已存過的、未通過檢查的、與已存路線終場相同的，分別列出數量並略過。
- **驗收**：重複按不會產生重複路線；失敗時不會寫入一半。

### B3｜實戰模式頁面

- 新路由（例如 `/battle`），版面以**窄視窗**（寬 420px 左右）為主要設計目標。
- 上方：目前牌組、先攻／後攻切換、目標 A～E 切換、手牌（5／6 張，可手動點選修正）。
- 結果：前 5 名（可設定 3～5），每條顯示：需要的起手卡、終場預覽（縮小版 `board-preview`）、有效干擾數、剩餘手牌、「已實測」／「AI 候選」標記。
- 選一條後：精簡步驟清單，目前步驟高亮；按鍵（空白鍵／方向鍵）或點擊前進、後退；最終終場一直顯示在步驟上方。
- 沒有任何符合的路線時，明確顯示「這手牌沒有已收錄的展開」，並提示可回 AI 分析補充。
- 手牌輸入方式此階段先沿用既有的「手動選卡」與「貼上截圖」。
- **驗收**：手牌輸入完成到結果出現，在一般電腦上感覺不到延遲（目標 < 300 ms）；420px 寬度下所有資訊不需水平捲動。

### B4｜一鍵截圖辨識（桌面版）

- Rust 端：新增 Tauri 指令，依視窗標題找到 Master Duel 視窗並截取其畫面，回傳影像給前端（可評估 `xcap` 或 Windows Graphics Capture）；找不到視窗時回傳清楚的錯誤。
- 全域快捷鍵（`tauri-plugin-global-shortcut`），預設例如 `Ctrl+Shift+Space`，可在設定中修改。
- 前端：取得截圖後，套用已記住的手牌位置版型，直接執行辨識；信心高的卡自動填入，不確定的卡讓使用者點選確認，然後立即產生 B3 的結果。
- 第一次使用時引導使用者框一次手牌位置並記住（以視窗的相對座標儲存，視窗移動或縮放後仍可用）。
- 瀏覽器版不提供此功能（維持貼上截圖）。
- **驗收**：從按下快捷鍵到結果出現 < 2 秒（辨識信心高的情況）；截圖不寫入磁碟。

### B5｜置頂小視窗（桌面版）

- 實戰模式可開成獨立的小視窗（Tauri 第二個 `WebviewWindow`），可切換「永遠在最上層」，記住位置與大小。
- 主視窗與小視窗共用同一份資料（IndexedDB 與目前牌組）。
- **驗收**：Master Duel 視窗模式下，小視窗可停在遊戲旁且不被遮住；關閉小視窗不影響主程式。

### B6｜後續（已同意，排在實戰模式之後）

- **自動更新**：Tauri updater，有新版時提示使用者更新（需要準備簽章金鑰與發布位置）。
- **Combo 分享碼**：把一條 Combo 壓縮成可貼到聊天軟體的短代碼，貼回即可匯入（走既有的 Combo 匯入驗證）。

## 風險與備案

| 風險 | 影響 | 備案 |
|---|---|---|
| 手牌辨識準確度不足（MD 卡圖與 YGOPRODeck 不同、手牌傾斜／重疊／光效） | B4 不可用 | 實作後若準確度不足：收集 8～10 張實際截圖與正確答案，評估改用更好的特徵或以 MD 截圖建立參考圖；在此之前 B3 仍可用手動選卡 |
| 「有效干擾數」是靜態估算，不是規則引擎結果 | 排序可能與實戰強弱有落差 | 介面標示「估算」；之後可依實戰回饋調整目標權重 |
| 收錄的路線不夠多 | 很多手牌顯示「沒有展開」 | B2 讓 AI 結果容易大量入庫；之後可配合「起手機率統計」找出覆蓋不到的起手 |
| KONAMI 條款 | 帳號風險 | 只做被動截圖、預設關閉、清楚說明，由使用者自行決定是否啟用 |
